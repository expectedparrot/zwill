Pew W158 Digital Twin Validation

Survey id: pew_w158
Respondent-level held-out answer predictions compared with what each respondent actually said. Error rate is the share where the model's highest-probability option was not the actual answer.

What this validation did

The question carbon_tax (“Do you favor or oppose the following proposals to reduce the effects of global climate change? Taxing corporations based on the amount of carbon emissions they produce”) was hidden from 100 respondents. For each respondent a digital twin — LLMs (1987d27fa67ff8d5 / openai:gpt-5.5, baseline_9500a89a78e2b4 / baseline:conditional-embedding) shown only that respondent's other survey answers — was asked to predict a full probability distribution over the hidden question's answer options. Each prediction is scored against the respondent's real answer with proper scoring rules (negative log-likelihood and Brier), then compared with two reference points: a uniform random guess and the survey's overall answer frequencies (the empirical baseline). A twin only demonstrates individual-level signal when it beats the empirical baseline — matching it just means reproducing the population average.

Reading the Respondents table below: each row is one respondent and the one question held out from them. Actual is their real answer; Predicted option probabilities is the twin's distribution over every option (the true option is tagged actual); p(actual) is the probability the twin placed on the truth (higher is better); NLL is −ln p(actual) (lower is better).

Does the twin beat chance?

1987d27fa67ff8d5 / openai:gpt-5.5 beats random chance.
On the held-out question it places 0.683 probability on each respondent's true answer versus 0.500 for a uniform random guess, and its NLL is 0.52 versus 0.69 for random (lower is better). It even edges the empirical-frequency oracle (NLL 0.52 vs 0.67) — note that oracle presumes you already know the population's answer split, so treat this as a bonus individual-signal check, not the fair bar.
baseline_9500a89a78e2b4 / baseline:conditional-embedding is mixed versus random chance.
On the held-out question it places 0.669 probability on each respondent's true answer versus 0.500 for a uniform random guess, and its NLL is 0.72 versus 0.69 for random (lower is better). It does not beat the empirical-frequency oracle (NLL 0.72 vs 0.67), i.e. it mostly reproduces the population's answer split rather than adding individual-level signal. That oracle is not the fair bar for a new question (you would not have the split), but it flags limited respondent-level targeting value.

Appendix: the conditional baseline and why it is a fair comparison

One of the models above is labelled baseline:conditional-embedding. It is not a digital twin. It is a deliberately cheap statistical model included to answer one question: is the frontier-model twin adding individual-level signal, or only rediscovering patterns a trivial model could find?

The two obvious baselines do not answer that. A uniform baseline uses no information. An empirical-marginal baseline uses the population distribution of the target question — it has no notion of the individual, and it is an oracle: for a genuinely new question, that distribution does not exist yet. The digital twin's whole claim is to predict a question no one has answered, using what a specific respondent said elsewhere. The conditional baseline is built to test exactly that claim on the cheap.

How it is built

  • Every question text, every (question, option) pair, and every option label is embedded once.
  • Each respondent is represented by the mean embedding of the options they actually chose — a compact summary of "what this person is like" — alongside their one-hot panel covariates (metadata such as party or region).
  • An XGBoost classifier scores each candidate option from the full feature set — the raw question and option embeddings, the respondent's covariates, and the embedding-similarity scalars — and the per-option scores are normalised into a distribution.

Why it is fair, not rigged

Training is leave-one-question-out: each held-out target is scored by a model trained only on the other questions. Nothing about the target — not a single respondent's answer to it, and not its marginal — ever enters training. The baseline therefore uses only what is genuinely available when predicting a new question: the wording of that question and its options, the respondent's answers to other questions, and the respondent's panel covariates — all of which the twin also has.

In particular, the baseline does not use the target question's own empirical marginal. That would be leakage: for a real new question the marginal is unknown, and the twin does not get it either. Because the features are semantic (embeddings, similarities, and demographics) rather than question identities, the fitted model transfers to target questions it has never seen — the same generalisation the twin claims.

How to read the comparison

A twin that cannot beat this baseline is not adding individual signal beyond cheap embedding similarity. A twin that does beat it — and beats the oracle empirical marginal — is contributing real predictive value about individuals, most plausibly from pretrained world knowledge that a small linear model cannot recover from the available questions alone.
